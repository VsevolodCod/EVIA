# Сохранённый результат анализа

Задача: [#76](https://github.com/VsevolodCod/EVIA/issues/76).

Сервер хранит привязку чата к одному источнику (`source_id`) и полный ответ
ассистента в `analysis_payload`: `{"version": 1, "response": AgentResponse}`.
Это снимок уже выданного ответа: SQL, ограниченная таблица, происхождение,
идентификатор запроса и серверные замеры времени. Открытие истории не запускает
модель и не пересчитывает результат по новой версии CSV.

Первый запрос в новый или старый непривязанный чат должен явно передать один
элемент `source_ids`. Привязка закрепляется перед вызовом модели. Запрос к другому
источнику возвращает HTTP 409; для него следует создать другой чат. Самостоятельный
`POST /agent/ask` сохраняет прежний контракт.

`GET /chats` и `GET /chats/{id}` возвращают `source_id`. История возвращает
`analysis_payload` у соответствующего сообщения ассистента. Старые записи имеют
`null`: они доступны для чтения, но утраченные детали восстановить задним числом
нельзя. Неизвестная версия payload отображается как текст с уведомлением.
Локальный кэш браузера не устанавливает серверную привязку и не даёт прав доступа.

## Обновление существующей установки

При запуске добавляются nullable-колонки `chats.source_id` и
`chat_messages.analysis_payload`. Повторный запуск не удаляет и не переписывает
историю. Каталог источников и файлы CSV этой миграцией не меняются.

Перед обновлением production:

1. Сделать согласованную резервную копию файла `CHAT_DB_PATH` через SQLite backup
   API. Простое копирование одного `.db` при активном WAL может потерять записи.
2. Проверить запуск новой версии на копии в отдельном каталоге, с отдельными
   `CHAT_DB_PATH`, `CATALOG_DB_PATH` и `BI_DATA_DIR`.
3. Сверить количество чатов/сообщений, чтение старой истории и повторный запуск.
4. После выпуска проверить новый вопрос, перезагрузку страницы и открытие его
   результата в браузере без прежнего localStorage.

Резервные копии содержат вопросы и результаты: хранить их вне репозитория.
При откате к прежнему коду дополнительные nullable-колонки можно оставить.
Прежний UI не покажет сохранённые детали, а новые ответы прежний backend будет
сохранять только текстом. Восстановление файла из backup отменит записи, созданные
после backup; не делать это без отдельного решения о таких данных.

## Границы

- Это история результатов, а не редактор сохранённых дашбордов (#28–30).
- Привязка источника не является авторизацией или изоляцией пользователей.
- Повтор HTTP после сбоя может создать ещё один вопрос: идемпотентность запросов
  остаётся отдельной задачей.
- Сохраняется серверное время ответа. Время ожидания конкретного браузера после
  перезагрузки не подменяется новым замером.
- Для живой PostgreSQL сохраняется результат на момент выполнения, а не копия БД.
