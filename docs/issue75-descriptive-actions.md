# Продолжение #75 после PR #78

PR #78 устраняет ложные ответы на вопросы о схеме и общем обзоре. Вопрос «Какие значения встречаются чаще всего?» оставался вне этого маршрута: LLM могла потратить десятки секунд и запросить ненужное уточнение. PR #79 добавляет hosted CI; данная ветка построена поверх него.

## Изменение поведения

- `frequencies`: точный top-5 непустых значений по выбранным полям, с детерминированным порядком при равных частотах. Без поля — явно обозначенный обзор максимум восьми полей, преимущественно категориальных, не отмеченных кандидатами ID. Это частоты отдельных полей, не сочетаний. Они вычисляются по всему snapshot, не по preview.
- `duplicates`: по умолчанию совпадение всех полей строки; при явном `columns` — повторения заданного ключа. Возвращаются число групп и число лишних строк сверх первой. Это не автоматическое доказательство бизнес-ошибки.
- `preview`: первые 10 строк без сортировки.
- Простые полные запросы выполняются без модели. Фильтрованные и составные запросы остаются в SQL-планировщике. Незнакомые формулировки LLM может направить в те же действия через `intent`, `columns`, `sql=null`; можно также выбрать `schema`/`dataset_overview` из #78.
- Имена полей сверяются с каталогом, SQL проходит общий guard, результаты связаны с source/snapshot/schema_version. Смена версии посреди действия не публикует смешанные результаты. Общий бюджет SQL стандартного действия — 10 секунд.
- Исправлено отклонение SQL с AND/OR: sqlglot представляет эти операторы как Func. Исключение сделано только для типов логических операторов; их дочерние выражения всё ещё проходят проверки.

## Диагностика задержки

В `timing.calls[]` добавлено необязательное `provider_total_ms`: исходный `total_duration` Ollama с переводом наносекунд в миллисекунды. Интерфейс показывает его отдельно от wall-time вызова, load/prompt/generation. Это позволяет отличать длительность внутри provider от окружающей обработки. Разность фаз не объявляется очередью или сетью без дополнительных данных.

Это диагностическое изменение, а не обещание ускорения произвольной генерации. Прогрев устраняет только холодную загрузку. #74 и общая приёмка #75 остаются открытыми; авто-закрытие issues в PR не используется.

## Проверка

Локальные Ollama, полный backend/frontend и browser suite не запускались по просьбе пользователя. Проверки предназначены для GitHub Actions из #79. Локально допустимы только чтение, проверка синтаксиса и diff.

Новые тесты покрывают частоты за пределами 500 строк, ведущие нули ID, пустой CSV, дубликаты по разному набору ключей, неизвестные поля, отказ от перехвата фильтрованного запроса, последовательные вопросы, модельный выбор metadata-действия, конкурентный reimport, AND/OR с запретом внешнего чтения и optional timing. Используются только синтетические данные и контролируемый provider; реальное качество/скорость Gemma этими тестами не подтверждается.

Предыдущие локальные замеры в другой ветке не считаются проверкой нового HEAD. Сценарии графиков/дашбордов используют командные изменения #73/#77 и не объявляются полностью принятыми данной доработкой. Структурированная память диалога, статистические гипотезы и прогнозирование остаются отдельными задачами.
