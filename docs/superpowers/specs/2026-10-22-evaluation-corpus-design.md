# Набор эталонов для оценки CSV-агента

## Цель

Дать задачам #14 и #15 версионируемый, воспроизводимый набор из 20 русскоязычных вопросов к CSV-источникам. Каждый однозначный вопрос должен иметь независимо проверяемый SQL и ожидаемый результат; неоднозначный или невозможный вопрос должен иметь ожидаемое безопасное действие.

## Границы данных

В Git хранятся только небольшие синтетические CSV-fixtures и их SHA-256. Исходные конкурсные CSV, строки пользователей и private manifest не коммитятся. Набор намеренно моделирует технические риски аудита: события и сессии, возвраты, цепочки попыток, NULL, даты, ведущие нули ID и десятичные значения.

## Формат v1

`evals/v1/cases.json` содержит 20 объектов с идентификатором, fixture, вопросом, видом ожидания и объяснением. Для `computed` указываются `gold_sql`, ожидаемые колонки, строки и допуск чисел. Для `clarify` и `refuse` SQL отсутствует, а ожидается причина и безопасный статус. Каждый fixture записан рядом как CSV и фиксируется SHA-256.

## Выполнение

`app/evaluation.py` загружает fixture через тот же `SourceService`, что UI, запускает gold SQL через read-only executor и сравнивает типизированные ячейки. Строки сравниваются в заданном порядке; NULL равен только NULL; числа сравниваются через `Decimal` с заданным допуском. Скрипт `python -m scripts.verify_eval_corpus` создаёт machine-readable JSON отчёт и возвращает ненулевой код при несоответствии hash, SQL, схемы или результата.

## Набор сценариев

Пять fixtures покрывают заказы/возвраты, сессии/события, цепочки попыток, склад и анонимную схему. В сумме 20 случаев включают count, sum, average, ratio-of-sums, группировку и сортировку, временной фильтр, NULL, отрицательные возвраты, leading-zero ID, отличие событий от сессий, отличие цепочек от попыток и три безопасных уточнения/отказа.

## Использование в #14

Бенчмарк будет передавать модели только вопрос и актуальную схему fixture. Его ответ считается корректным только если безопасный статус совпадает либо выполненный результат совпадает с gold-результатом; совпадение текста SQL само по себе не является успехом.
