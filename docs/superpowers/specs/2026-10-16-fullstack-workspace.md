# Линза BI: рабочее пространство, issue #1

Утверждено Всеволодом в разговоре 16 октября 2026: вариант «Аналитика в центре», создание issue и реализация до PR.

## Пользовательский результат
Слева источники и история текущей вкладки, в центре реальные данные/схема/результаты, справа чат с Markdown. Маскот Эвия рядом с вводом отражает ожидание, обработку и ошибку; тихий режим и системное уменьшение движения. На узких экранах области складываются без потери управления.

## Контракт
Используются существующие GET /health, GET /sources, POST /sources/csv (multipart file), GET /sources/{id}/schema, /preview?limit=100, /profile и POST /agent/ask {question, source_ids}. Ответ: {answer, steps, tool_results:[{tool_name,ok,data,error}]}. API-клиент проверяет ответы; ошибки запроса видны и допускают повтор. Источник закреплён за диалогом, поздний ответ не попадает в другой диалог.

## Границы
Движок и агент команды сохраняются. История UI не выдаётся за серверную память агента. Обзор использует точное количество строк из схемы и явно выборочные статистики профиля. Существующий mock подписан как демонстрационный. Нет выдуманных графиков, прогресса, аналитических цифр или отключённых декоративных действий. Поддержка SQL и CSV с ';' остаётся зависимостью A/B.

## Безопасность и автономность
Markdown/GFM без raw HTML, удалённых картинок и опасных URL. API того же origin, Vite proxy при разработке; никаких облачных вызовов в интерфейсе, CDN или внешних шрифтов. Загруженные данные и диалоги не пишутся в frontend storage. Настройка тихого режима может храниться локально. Учебный CSV разрешён, конкурсные данные и секреты исключены из git.

## Поставка
React + TypeScript + Vite в frontend/. FastAPI отдаёт готовый frontend/dist после существующих API-маршрутов. Команды подготовки и единый Python launcher для локального dev/production. PR из issue-1-fullstack-workspace в tes/pipeline_1, без merge и закрытия issue.
