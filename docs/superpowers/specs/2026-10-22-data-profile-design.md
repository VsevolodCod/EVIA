# Достоверный профиль неизвестного датасета — дизайн

Связано с #8. Профиль должен давать пользователю и агенту факты о конкретной версии загруженного источника. Расчёт не должен подменять полный датасет выборкой и не должен трактовать пустую строку, `NULL` и ноль как одно значение.

## Граница и результат

Для CSV-источника EVIA строит паспорт по его текущему `snapshot_id` после успешного импорта. Паспорт отдаётся через существующий endpoint профиля и используется экраном аналитики и инструментом агента. Новая версия CSV получает новый профиль; старые данные не переиспользуются.

Профиль разделяет показатели на два уровня:

- **Полный набор:** точное количество строк, непустых значений, `NULL`, пустых строк, уникальных значений, доля уникальности, минимум/максимум/сумма/среднее для чисел и границы периода для дат.
- **Выборка:** пять наиболее частых текстовых значений и примеры. В ответе явно записываются размер выборки, число обработанных строк и охват `full` либо `sample`.

## Контракт

Каждая колонка содержит полные счётчики и типизированный блок, применимый только к подходящему типу. Числовые агрегаты сериализуются как строки, чтобы не терять точность `DECIMAL`; даты — в ISO-формате. `NULL` учитывается отдельно от пустой строки. Неизвестные или смешанные поля остаются текстом и не получают числовую статистику.

Кандидат идентификатора отмечается только при отсутствии `NULL` и пустых строк и при точной уникальности на всех строках. Это кандидат, а не утверждение о бизнес-ключе. Составные ключи в #8 не подтверждаются автоматически.

## Расчёт и производительность

DuckDB считает полные агрегаты одним запросом на колонку над typed-таблицей и raw-таблицей. Значения берутся из raw-таблицы для различения пустых строк и `NULL`; числовые и временные операции — только из typed-таблицы после проверки типа импорта. Топ-значения ограничены пятью результатами и считаются из ограниченной выборки, чтобы не превращать открытие экрана в тяжёлую сортировку всего источника.

Расчёт выполняется по запросу, но ответ помечает снимок, для которого он получен. Повторный импорт создаёт другой `snapshot_id`, поэтому UI и агент не смогут выдать профиль прошлого набора как текущий. Доступ к DuckDB остаётся согласованным с read-only SQL-запросами.

## Ошибки и отображение

Если полный профиль недоступен, endpoint возвращает контролируемую ошибку, а интерфейс показывает возможность повторить расчёт. UI не подставляет старый результат. Карточки показывают, что статистика точная по полному датасету; топ-значения подписаны как выборочные.

## Проверка

Тесты фиксируют:

- раздельный учёт `NULL`, пустой строки и нуля;
- точные числовые агрегаты и сохранение decimal comma;
- диапазоны дат;
- точную уникальность и кандидата ID;
- отсутствие числовой статистики у смешанной колонки;
- разные профили до и после повторного импорта;
- контракт API и отображение охвата в интерфейсе;
- проверку девяти исходных CSV без публикации их строк в репозитории.
