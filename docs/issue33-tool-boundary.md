# Проверка вызовов инструментов агента

Модель получает JSON Schema как подсказку, но сервер повторно проверяет весь
объект аргументов, включая вложенные поля, типы, диапазоны и запрещённые ключи.
Некорректный вызов получает фиксированный код `INVALID_TOOL_ARGUMENTS` и не
достигает обработчика. Неизвестный инструмент не выполняется.

Обычные исключения обработчика могут содержать DSN, пути или строки данных;
модель и клиент получают только `TOOL_EXECUTION_FAILED`. Для ожидаемых ошибок
используются отдельные стабильные коды: `INVALID_SOURCE_FIELD`,
`QUERY_REJECTED` и коды PostgreSQL. Сырые исключения не включаются в результат
инструмента или продолжение диалога. Схема не заменяет проверку прав на источник
и read-only SQL executor.

В каждом запросе агент сверяет прямые `source_id` и косвенные ссылки на
сохранённые графики/дашборды с выбранным источником. Инструкция внутри CSV,
имени столбца или результата инструмента не расширяет этот список. В реестре
нет инструментов выполнения Python, shell или сетевых запросов; SQL исполняется
только через ограниченный read-only слой.

Модель получает не более 10 строк предпросмотра. Длинные значения полей
идентификаторов маскируются, строки ограничиваются 200 символами; в профиле
не передаются значения ID и редкие значения с частотой 1. Полный профиль и
предпросмотр для владельца остаются доступными через обычные API, чтобы UI
показывал исходные данные. Это минимизация примеров для модели, а не
анонимизация произвольного аналитического SQL.

Серверный `X-Request-ID` совпадает с `AgentResponse.request_id`. Логи содержат
метод, маршрут, статус, длительность и тип ошибки; traceback и текст исключения
не печатаются. Диагностика не сохраняет вопрос, строки CSV, DSN и ключи.

Тесты: `pytest tests/test_tool_boundary.py tests/test_tool_agent_release.py tests/test_agent_security.py`.
