# Проверка общего цикла инструментов после #117

Основа исправления — main `460ba88`. В [CI этого SHA](https://github.com/VsevolodCod/EVIA/actions/runs/40733204178)
backend: 68 failed, 268 passed, 4 skipped; frontend прошёл, browser не запущен.

## Что исправляется

- Фабрика `build_tool_registry(catalog, sources)` снова собирает полноценные
  repositories/executor/dashboard engine. Явная передача зависимостей из main
  остаётся доступна.
- Вход `ChartModel(id=...)` совместим с новым chart_id, старое свойство `.id`
  доступно интеграциям. GET /charts/{id} возвращает оба имени ID.
- Старое имя инструмента get_dashboard поддерживается вместе с
  get_dashboard_info: история и интеграции могут читать прежние панели.
- Отсутствующий dashboard_id не передаётся внешним реализациям агента как новый
  обязательный keyword. Это устраняет 502 и сбой проверки гонки привязки чата.
- Результат query_data сохраняется в AgentResponse.results, включая provenance,
  и восстанавливается из истории. Результаты вычислений не исчезают при переходе
  от JSON-планировщика к вызовам инструментов.
- Явные source_id в аргументах инструмента, в том числе внутри definition и
  filters, проверяются относительно источников текущего запроса. Выход за scope
  возвращает SOURCE_SCOPE_VIOLATION без исполнения инструмента.
- Исчерпание max_steps без итогового ответа возвращается как ошибка с trace,
  а не успешный ответ. Оборванные аргументы инструментов не исполняются.

## Что именно проверяют тесты

Проверки удалённых CSVQueryAgent/DashboardDraft заменены вызовами реальных
инструментов общего агента. Ничего не помечено xfail/skip ради зелёного CI.
Выбор инструмента моделируется scripted LLM; CSV, DuckDB, HTTP, SQLite,
сохранение и повторный расчёт выполняются по-настоящему в CI.

- Семь последовательных HTTP-вопросов: профиль/схема, частоты, дубликаты,
  предпросмотр, история, конфликт источника и новый чат. Кэш профиля проверяется
  отдельно от количества обращений к модели.
- Сумма SQL 300, сохранение результата, restart, обновление источника до 999,
  удаление источника и доступность архивной истории.
- Дашборд: три схемы, KPI 145 и кварталы 60/40/-5/50, реальные сохранённые
  определения, повторное открытие базы; bar/scatter/table и все календарные шаги.
- Ошибочные поля/операторы/шаги не оставляют сохранённых карточек; ID 001
  остаётся строкой; область выбранного источника проверяется на query и chart.
- Числовые проверки оставшегося descriptive_answer (IQR, группы, нулевой IQR,
  редкие значения, дубликаты, частоты) теперь вызывают сам калькулятор. Это
  модульная проверка формул, не доказательство его доступности через общий агент.

## Границы готовности

После #117 вопросы о схеме/обзоре также проходят через модель. Старые проверки
«0 вызовов LLM» и старые живые p95 от другого pipeline больше не подтверждают
производительность текущего агента. Необходимо повторить #74/#75 на Railway.

Модель выбирает инструменты и пишет текст. Скриптовые fixtures проверяют
интеграцию, но не доказывают правильность выбора реальной Cloud.ru или любой
другой модели. Полная матрица #35, живое переоткрытие #29, смысловой контекст
#17, автономная поставка #34 и сравнение двух моделей #14 остаются открытыми.

Scope по явным source_id не заменяет всю проверку #33: артефактные ID,
минимизация данных и adversarial-прогоны требуют отдельного аудита.

Тяжёлые проверки — только GitHub Actions. Локально выполнены синтаксический
разбор Python и git diff --check; приложение, Ollama и полный pytest не запускались.
