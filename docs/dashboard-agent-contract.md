# DashboardSpecV1

EVIA строит текущий дашборд из фактически полученных строк: предпросмотра
источника или одной успешной табличной выдачи инструмента. Это безопасный
режим до подключения аналитической модели: интерфейс не добавляет метрики,
которых нет в данных.

Когда агент начнёт планировать аналитику, он может возвращать необязательное
поле `dashboard_spec` рядом с существующими `answer` и `tool_results`.
Контракт ниже описывает целевой формат; бэкенд пока его не исполняет.

```json
{
  "version": 1,
  "title": "Продажи за 2026 год",
  "summary": "Выручка растёт с марта и достигает пика в июле.",
  "palette": ["#518ed5", "#ddaa65", "#8873bb"],
  "cards": [
    { "type": "kpi", "label": "Выручка", "value": 1284000, "format": "number" },
    { "type": "line", "title": "Выручка по месяцам", "x": "month", "y": "revenue", "aggregate": "sum" },
    { "type": "bar", "title": "Продажи по категориям", "x": "category", "y": "revenue", "aggregate": "sum" }
  ]
}
```

`version` обязателен и равен `1`. Разрешены только поля из таблицы конкретного
инструмента. Для `kpi` агент передаёт уже рассчитанное число только вместе с
точным названием показателя; для графиков передаются имена полей и одна из
разрешённых агрегаций: `count`, `sum`, `avg`, `min`, `max`. Клиент должен
отбросить неизвестный тип карточки, неизвестное поле, невалидную палитру или
некорректную агрегацию и показать существующую таблицу. Палитра — от двух до
двенадцати `#RRGGBB`; пользовательская палитра имеет приоритет над ответом
агента.

Этот контракт намеренно не разрешает HTML, SQL или произвольный JavaScript.
Текст выводов остаётся отдельным Markdown-ответом и не управляет интерфейсом.
