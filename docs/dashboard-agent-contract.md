# DashboardSpecV1

EVIA формирует дашборд на основе аналитической спецификации, которую возвращает агент. Спецификация описывает карточки, используемые поля, агрегаты, фильтры и параметры отображения. Она не содержит SQL, HTML или исполняемого кода.

Агент не должен самостоятельно придумывать численные результаты. Backend проверяет спецификацию, определяет доступность полей и источников, выполняет разрешённые вычисления и возвращает данные для отображения. До реализации этого механизма клиент продолжает использовать фактически полученные строки: предпросмотр источника или успешную табличную выдачу инструмента.

Спецификация может передаваться в необязательном поле `dashboard_spec` рядом с существующими `answer` и `tool_results`. Текстовый ответ и спецификация дашборда являются независимыми частями ответа агента.

## Формат

```json
{
  "version": 1,
  "title": "Продажи за 2026 год",
  "summary": "Краткий вывод по результатам анализа",
  "palette": ["#518ed5", "#ddaa65", "#8873bb"],
  "filters": [],
  "cards": [
    {
      "id": "monthly_revenue",
      "type": "line",
      "title": "Выручка по месяцам",
      "x": {
        "source_id": "sales_source",
        "field": "month",
        "type": "temporal",
        "label": "Месяц",
        "sort": "asc"
      },
      "y": {
        "source_id": "sales_source",
        "field": "revenue",
        "aggregate": "sum",
        "label": "Выручка",
        "format": {
          "type": "number",
          "decimals": 0
        }
      },
      "series": null,
      "filters": [],
      "limit": 100
    }
  ]
}
```

## Общие поля

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `version` | integer | Да | Версия контракта. Для этой схемы — `1`. |
| `title` | string | Да | Название дашборда, не более 200 символов. |
| `summary` | string или null | Нет | Краткое текстовое описание результатов анализа. Не является доказательством корректности вычислений. |
| `palette` | string[] | Нет | Палитра графиков. От 2 до 12 цветов в формате `#RRGGBB`. |
| `filters` | Filter[] | Нет | Общие фильтры дашборда. |
| `cards` | Card[] | Да | Список карточек в порядке отображения. Должен содержать хотя бы одну карточку. |

Неизвестные поля спецификации не должны молча менять поведение интерфейса. Клиент и backend должны валидировать контракт по версии и соответствующей схеме.

## Ссылки на поля

Каждая ссылка на поле имеет следующий формат:

```json
{
  "source_id": "sales_source",
  "field": "revenue"
}
```

`source_id` — идентификатор зарегистрированного источника данных, а `field` — точное имя поля в его схеме.

В карточках `x`, `y`, `series` и фильтры используют ссылки на поля. Для KPI ссылка на поле задаётся в `field`.

Если поле отсутствует в схеме источника или источник недоступен для текущего запроса, backend не должен выполнять вычисление.

Разные карточки одного дашборда могут обращаться к разным источникам. Поля одной карточки могут ссылаться на разные источники только при поддержке и проверке межтабличных связей backend. Наличие нескольких `source_id` само по себе не разрешает объединение таблиц.

## Агрегации

Поддерживаемые значения `aggregate`:

- `count` — количество строк в группе;
- `sum` — сумма ненулевых числовых значений;
- `avg` — среднее арифметическое ненулевых числовых значений;
- `min` — минимальное значение;
- `max` — максимальное значение.

Агрегация применяется backend к разрешённому полю. `sum` и `avg` допустимы только для совместимых типов данных. `min` и `max` требуют упорядочиваемого типа.

`count` считает строки группы, а не количество ненулевых значений поля. Для подсчёта уникальных значений в будущем может быть добавлен отдельный агрегат `count_distinct`.

## Форматирование

Объект `format` определяет отображение вычисленного значения:

```json
{
  "type": "number",
  "decimals": 2
}
```

Поддерживаемые типы:

- `number` — число;
- `integer` — целое число;
- `percent` — процент;
- `currency` — денежное значение.

`decimals` — необязательное целое число от 0 до 6. Для `currency` дополнительно может задаваться `currency`, например `RUB`.

Форматирование не изменяет само вычисленное значение. Для `percent` backend и клиент должны придерживаться единой семантики: значение `0.15` отображается как `15%`, если формат не предусматривает иное.

## Фильтры

Фильтр имеет вид:

```json
{
  "field": {
    "source_id": "sales_source",
    "field": "status"
  },
  "operator": "in",
  "value": ["paid", "completed"]
}
```

Объект фильтра содержит:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `field` | FieldRef | Да | Источник и поле, к которым относится условие. |
| `operator` | string | Да | Оператор из разрешённого списка. |
| `value` | любое JSON-значение | Зависит от оператора | Значение или список значений для сравнения. |

Разрешённые операторы:

- `eq` — равно;
- `ne` — не равно;
- `gt`, `gte` — больше, больше или равно;
- `lt`, `lte` — меньше, меньше или равно;
- `in`, `not_in` — входит или не входит в список значений;
- `between` — находится в заданном диапазоне;
- `is_null`, `is_not_null` — значение отсутствует или присутствует.

Для `is_null` и `is_not_null` поле `value` не передаётся. Для `in` и `not_in` требуется непустой массив ограниченного размера. Для `between` требуется массив из двух значений совместимого типа.

Backend проверяет совместимость значения фильтра с типом поля и применяет фильтр только к разрешённому источнику.

Фильтры дашборда применяются ко всем карточкам, для которых их можно корректно интерпретировать. Фильтры карточки действуют только на соответствующую карточку. Если общий фильтр нельзя применить к конкретной карточке, backend не должен молча игнорировать его: он должен явно определить ошибку или неприменимость фильтра согласно принятой политике.

До появления механизма связей между источниками глобальные фильтры могут применяться только к совместимым источникам и полям.

## Сортировка и ограничения

`sort` задаёт порядок значений оси X:

- `asc` — по возрастанию;
- `desc` — по убыванию;
- `label_asc` — по подписи по возрастанию;
- `label_desc` — по подписи по убыванию.

Для категориальных диаграмм рекомендуется сортировка по агрегированному значению. Для временных рядов — по времени.

`limit` — положительное целое число, ограничивающее количество отображаемых точек или категорий. Рекомендуемый верхний предел — 1000; для отдельных типов визуализаций может применяться более строгий предел.

Ограничение применяется после группировки и сортировки. Backend должен определять порядок операций однозначно, чтобы результат не зависел от реализации конкретного адаптера.

## Палитра

Палитра содержит от 2 до 12 строк вида `#RRGGBB`. Невалидная палитра не должна приводить к исполнению пользовательского кода или произвольному изменению стилей.

Если пользователь выбрал собственную палитру, она имеет приоритет над палитрой агента. При отсутствии валидной палитры применяется стандартная палитра приложения.

## Безопасность и ошибки

Спецификация не разрешает SQL, HTML, JavaScript, произвольные выражения или имена таблиц вне зарегистрированного каталога.

Backend обязан проверять источники, поля, агрегаты, фильтры, ограничения и совместимость типов до выполнения вычислений. Межтабличные объединения допускаются только при наличии разрешённых и однозначно определённых связей.

При ошибке одной карточки предпочтительно возвращать её статус ошибки, не теряя остальные успешно рассчитанные карточки. Некорректная спецификация целиком отклоняется, если её структура не позволяет безопасно определить набор вычислений.

До реализации backend-исполнителя этот контракт описывает целевой формат и не означает, что все перечисленные функции уже поддерживаются. Клиент продолжает использовать существующий безопасный режим отображения фактически полученных данных.
