# Достоверное представление табличных результатов (#27)

Исправлены три дефекта ResultVisualization: исчезновение категорий после двенадцатой,
отрицательная SVG-высота для возвратов/убытков и выбор числового ID как показателя.

- Шкала включает ноль, отрицательные и положительные значения. Значения таблицы
  не меняются; renderer не агрегирует и не сортирует исходный результат.
- Все строки доступны на страницах по 50 точек с явным диапазоном. Шкала общая
  для всего результата. NULL создаёт разрыв линии и видимое предупреждение.
- QueryResult передаёт типы полей до графика. Строковые/временные/boolean поля и
  идентификаторы не выбираются как меры. Для старых нетипизированных результатов
  сохраняется числовой разбор, но исключаются ID-имена и коды с ведущими нулями.
  Это эвристика совместимости, не полноценный semantic catalog.
- При нескольких показателях пользователь выбирает нужный; доступны отдельные
  подписи. Переход table/bar/line не обращается к модели и сохраняет числа.
- GeneratedDashboard показывает `limit_reached` в печатаемом содержимом: достигнутый
  предел не выдаётся за доказательство дополнительных групп или полной выдачи.

Регрессии: `ResultVisualization.test.tsx`, `resultChartModel.test.ts`,
`GeneratedDashboard.test.tsx`, существующие `ToolResults.test.tsx` и
`AnalysisResult.test.tsx`. Проверяются 13/101 категорий, смешанные знаки, нули,
малые/большие значения, ID `001`, типизированные decimal/string, выбор показателя,
NULL/повторяющиеся подписи и смена источника. Полный frontend/build/backend/browser
выполняется в GitHub Actions. Реальная модель для этих исправлений не требуется.

Refs #27, #26, #31. Полные задачи #26/#31 остаются шире: typed bar/scatter/table,
временная гранулярность, версия метрики и сквозная приёмка паспорта здесь не реализуются.
