# Интеграция «Линза BI», 17 октября 2026

## Основа и объём

Объединены UI `issue-1-fullstack-workspace` (`26ea8c8`) и backend `tes/pipeline_1` (`a27cefe`). Их общая база — согласованный `929b8dd`. Ветка результата: `integration/linza-workspace`; целевая ветка PR — `tes/pipeline_1`. Слияние PR оставлено команде.

Сохранены интерфейс React/TypeScript/Vite, API-модули, схема, предпросмотр, выборочный профиль, безопасный Markdown/GFM, результаты инструментов, история в памяти вкладки и существующие SVG Эвии. В шапке и заголовке страницы восстановлено имя продукта «Линза BI»; Эвия — помощник. Вопрос отправляется как `{question, source_ids: [id]}` в `/agent/ask`.

## Изученные материалы

Прочитан предоставленный `Кейс№2_AI-Native BI Система_ИАЦ.docx`: первичное знакомство с данными и ответы по содержимому — ближайшие сценарии; графики, дашборды и контекст диалога описывают более широкий итоговый продукт. В этой интеграции действуют границы задачи участника C.

Изучен [README HK_Datasets](https://gitverse.ru/kban/HK_Datasets/content/main/README.md), включая описания всех девяти таблиц. Он называет кейс №1, тогда как локальный документ — №2. Датасеты используют UTF-8, разделитель `;`, десятичную запятую и текстовые идентификаторы; даты и время имеют отдельные форматы, некоторые поля обозначены как МСК. Это необходимо учесть в Data Engine. Весь набор CSV не скачивался и не импортировался. Поддержка конкурсного формата остаётся зависимостью от A/B; преобразование данных за пользователя не выполнялось.

## Исправленные несовместимости

- В актуальном агенте `history=None` приводила к `TypeError` при вызове `/agent/ask`. Отсутствующая история теперь трактуется как пустая, переданная история не изменяется.
- SQLAlchemy-каталог не создавал таблицы на чистом запуске. Добавлена инициализация metadata при создании собственного engine; проверены повторное открытие и совместимость с прежними таблицами SQLite.
- Для lifespan новой ветки отсутствовали `aiosqlite` и async-зависимость `greenlet`. Они устанавливаются через `requirements.txt`; дублирующий пакет `dotenv` удалён, `python-dotenv` сохранён.
- Настройка `BI_CATALOG_DB` поддерживается как прежнее имя; `CATALOG_DB_PATH` имеет приоритет. Пути по умолчанию следуют `BI_DATA_DIR`, чтобы изолированные проверки не затрагивали рабочие базы.
- Раздача frontend подключена после всех API-маршрутов, включая новые серверные чаты.
- Windows dev-launcher напрямую владеет процессом Vite, без промежуточного `npm.cmd`. Добавлена обработка `Ctrl+Break`; проверены остановка и закрытие обоих портов.
- Тесты задают UTF-8 явно и разделяют проверку выхода за каталог и symlink, чтобы отсутствие привилегии не скрывало проверку обхода пути.

## Проверки

Окружение: Windows, Python 3.11.0, Node.js 24.22.0, установленный Microsoft Edge, Playwright 1.64.0. Node установлен переносимым архивом из nodejs.org вне git с проверкой SHA-256. Зависимости frontend установлены через `npm ci` без изменения lock-файла.

| Проверка | Результат |
| --- | --- |
| `npm --prefix frontend test` | 24 теста успешно |
| `npm --prefix frontend run build` | TypeScript и production build успешно |
| Backend и HTTP-сценарии | 16 тестов успешно; 2 платформенных пропуска |
| `BI_BROWSER_TESTS=1`, Edge, `pytest tests/browser -q` | 1 браузерный тест успешно |

HTTP-проверки используют реальные FastAPI, SQLite и CSV-адаптер: пустой список → загрузка синтетического CSV → схема → предпросмотр с ведущими нулями → профиль → mock-агент → реальные табличные `tool_results`. Отдельно проверены production-раздача bundle, dev-прокси на нестандартном порту, остановка launcher и освобождение портов.

Браузер: ширины 1440 и 390 px, отсутствие горизонтального переполнения страницы, загрузка через клавиатуру, Ctrl+Enter, точный `source_ids`, реальные таблицы, восстановление ответа при смене источника, тихий режим и reduced-motion. На синтетическом вредоносном ответе проверены GFM-таблица, список и код, отсутствие исполняемых HTML/script и внешних запросов изображений. Ошибок JavaScript не обнаружено. Снимки просмотрены и оставлены вне git в `frontend/test-results/`.

Компонентные проверки покрывают поздние ответы и предпросмотры после переключения источника, повтор после ошибки API, отмену ожидания, состояния Эвии, пустые таблицы, разнородные результаты инструментов и безопасность Markdown.

## Ограничения

- Пропущены POSIX-проверка групп процессов и symlink-проверка, требующая Developer Mode/привилегии Windows. HTTP-проверки остановки Windows выполнены.
- Без переменной `BI_BROWSER_TESTS=1` браузерный тест пропускается отдельно. Другие браузеры, ОС и экранный диктор не проверялись.
- Проверена интеграция с mock, качество ответов настоящей LLM не оценивалось. Унаследованный mock вызывает инструмент только в первом запросе экземпляра провайдера; последующие ответы могут быть только текстовыми.
- `/agent/chat` и постоянные серверные сессии сохранены из backend, но UI их не вызывает и их полная работоспособность здесь не утверждается. При чтении кода обнаружен отдельный риск backend: `get_or_create()` для существующего постоянного чата возвращает `ChatHistoryResponse`, а `save()` ожидает `Chat`. Это следует исправить и проверить до подключения постоянных сессий.
- SQL/DuckDB/Text-to-SQL, конкурсный разделитель, большие файлы, графики и дашборды остаются вне объёма. Ни конкурсных CSV, ни секретов в git не добавлено.
