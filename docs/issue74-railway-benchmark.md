обзор не вызывали модель; SQL использовал три вызова Cloud.ru на вопрос.

  67, 70, 68, 68, 69, 67, 70, 70, 60, 65, 65, 71, 66, 63.
- Обзор: 124, 120, 121, 123, 111, 116, 115, 124, 128, 120, 119, 124,
  127, 126, 133, 133, 129, 123, 122, 118, 126, 145, 127, 134, 136, 128,
  133, 137, 127, 124.
- SQL: 6058, 5324, 5236, 4861, 4675.

Это `AgentTiming.elapsed_ms` внутри Railway, без браузерной сети и
рендеринга. Первый запрос каждого сценария измерен отдельно, но не означает
холодную загрузку весов у Cloud.ru. Исторические 194,7 с получены на другом
локальном стенде с Ollama и не сравниваются напрямую с этой серией.

Воспроизвести на Railway после развертывания скрипта:

```sh
railway ssh -p f0ae576b-cde6-4314-939b-dd961cb0e139 -s EVIA -e production -- python -m scripts.benchmark_railway_agent
```

Скрипт откажется запускаться без `RAILWAY_ENVIRONMENT`, создаст временный CSV
и каталог, выведет сырые времена и p50/p95. Он проверяет факты схемы/обзора
и вычисленный SQL-результат. Для других размеров прогона есть
`--schema-repeats`, `--overview-repeats` и `--sql-repeats`.

Реальный Cloud.ru успешно вернул вычисленный результат. Ошибочный SQL
отдельно проверен в #75 и PR #124: `QUERY_REJECTED`, не сообщение о лимите
шагов. API-тест `tests/test_chat_persistence.py` проверяет отдельный HTTP 502
при отказе модели. Реальный отказ Cloud.ru не вызывался принудительно.
Браузерный p95 и lifecycle долгих операций относятся к #32/#35.
