# Методы проверки гипотез

Документ описывает два метода модуля `app/hypothesis`: `compare` и
`relationship`.

## 1. Сравнение двух групп --- `compare`

### Назначение

Метод сравнивает одну агрегированную метрику для двух выборок --- `left`
и `right`. Группы задаются собственными фильтрами.

Подходящие вопросы:

-   Изменился ли средний чек после изменения процесса?
-   Стало ли заказов больше в выбранный период?
-   Отличается ли суммарная выручка в двух категориях?

Метод описывает наблюдаемую разницу, но сам по себе не доказывает, что
она вызвана конкретным событием.

### Параметры

| Поле          | Назначение                                                             |
|---------------|------------------------------------------------------------------------|
| `method`      | Тип проверки: `compare`.                                               |
| `id`          | Идентификатор проверки.                                                |
| `description` | Человекочитаемое описание проверки.                                    |
| `metric`      | Метрика, рассчитываемая для обеих групп.                               |
| `left`        | Первая группа и её фильтры.                                            |
| `right`       | Вторая группа и её фильтры.                                            |
|   `expected`  | Ожидаемое направление: `increase`, `decrease`, `no_change` или `any`.  |

### Метрика `MetricSpec`

| Поле          | Назначение                                                |
|---------------|-----------------------------------------------------------|
| `source_id`   | Идентификатор источника данных.                           |
| `aggregation` | `sum`, `count`, `count_distinct`, `avg`, `min` или `max`. |
|   `field`     | Поле для агрегации; для `count` может не требоваться.     |


Значения агрегаций: `sum` --- сумма, `count` --- число строк,
`count_distinct` --- число уникальных значений, `avg` --- среднее, `min`
и `max` --- минимум и максимум.

### Группы и фильтры

Каждая группа имеет собственный список `filters`. Это позволяет
сравнивать периоды, категории или сегменты. Если фильтры не заданы,
группа охватывает все строки источника, доступные запросу.

``` json
{
  "method": "compare",
  "id": "avg-before-after",
  "description": "Сравнить среднюю сумму до и после изменения",
  "metric": {
    "source_id": "orders",
    "aggregation": "avg",
    "field": "amount"
  },
  "left": {
    "label": "До",
    "filters": [
      {"field": "period", "operator": "eq", "value": "before"}
    ]
  },
  "right": {
    "label": "После",
    "filters": [
      {"field": "period", "operator": "eq", "value": "after"}
    ]
  },
  "expected": "increase"
}
```

Пример условный: замените `source_id` и поля на реальные имена из
источника.

### Интерпретация

Реализация рассчитывает значение метрики для обеих групп, разницу
(`delta`), процентное изменение (`change_percent`), направление и оценку
относительно `expected`.

-   Положительная разница: `right` больше `left`.
-   Отрицательная разница: `right` меньше `left`.
-   Нулевая разница: рассчитанные значения равны.
-   Процентное изменение зависит от исходного значения; при нулевой базе
    процент может быть неопределённым.

`expected` задаёт ожидаемое направление изменения. Это не отдельный
статистический тест значимости и не доказательство причинности.
Для `avg` при минимум двух числовых наблюдениях в каждой группе результат
также содержит размер выборки, p-value и 95% доверительный интервал разницы
по методу Уэлча. Он предполагает независимость наблюдений. Для `sum`,
`count`, `min` и `max` неопределённость явно отмечена как неоценённая;
направление разницы остаётся описательным выводом.

## 2. Проверка связи --- `relationship`

### Назначение

Метод оценивает корреляционную связь между двумя агрегированными
метриками. Данные группируются по одному, двум или трём полям; для
каждой группы формируется пара значений `x` и `y`.

Примеры вопросов:

-   Связаны ли количество заказов и выручка по месяцам?
-   Связаны ли расходы и продажи по подразделениям?
-   Есть ли линейная связь между показателями по категориям?

Корреляция показывает совместное изменение показателей, но не
устанавливает причинно-следственную связь.

### Параметры

| Поле                 | Назначение                                                             |
|----------------------|------------------------------------------------------------------------|
| `method`             | Тип проверки: `relationship`.                                          |
| `id`                 | Идентификатор проверки.                                                |
| `source_id`          | Источник данных.                                                       |
| `x_metric`           | Первая агрегированная метрика.                                         |
| `y_metric`           | Вторая агрегированная метрика.                                         |
| `group_by`           | От 1 до 3 полей группировки; может включать временную гранулярность.   |
| `filters`            | Общие фильтры выборки.                                                 |
| `relationship`       | Тип проверяемой связи; текущая реализация ориентирована на корреляцию. |
| `correlation_method` | Метод корреляции; по умолчанию `pearson`.                              |
| `alpha`              | Уровень значимости для статистической оценки.                          |
| `confidence_level`   | Уровень доверительного интервала.                                      |
| `max_lag`            | Число проверяемых календарных лагов, от 0 до 6.                        |

Для каждой `MetricExpression` задаются `aggregation` и `field`; для
`count` поле может не требоваться. Допустимые агрегации: `sum`, `count`,
`count_distinct`, `avg`, `min`, `max`.

### Группировка

`group_by` содержит от одного до трёх полей. Для временного поля можно
указать гранулярность:

-   `day` --- день;
-   `week` --- неделя;
-   `month` --- месяц;
-   `quarter` --- квартал;
-   `year` --- год.

Например, группировка по месяцу формирует по одной паре агрегированных
значений на каждый месяц. Статистика затем рассчитывается по этим парам,
а не по каждой исходной строке.

### Пример

``` json
{
  "id": "monthly-relationship",
  "method": "relationship",
  "source_id": "sales",
  "x_metric": {
    "aggregation": "sum",
    "field": "orders_count"
  },
  "y_metric": {
    "aggregation": "sum",
    "field": "revenue"
  },
  "group_by": [
    {"field": "month", "granularity": "month"}
  ],
  "filters": [],
  "relationship": "correlation",
  "correlation_method": "pearson",
  "alpha": 0.05,
  "confidence_level": 0.95,
  "max_lag": 2
}
```

Имена источника и полей условные; сверяйте структуру с моделью
`RelationshipCheck`.

### Расчёт и результат

Реализация использует корреляцию Пирсона (`pearson`). Коэффициент лежит
в диапазоне от `-1` до `1`:

-   около `1` --- положительная линейная связь;
-   около `-1` --- отрицательная линейная связь;
-   около `0` --- слабая или отсутствующая линейная связь.

Коэффициент около нуля не исключает нелинейную зависимость.

Результат включает статистические показатели, в том числе коэффициент
корреляции и p-value, а при достаточном количестве наблюдений ---
доверительный интервал. Пары с отсутствующими или не конечными числовыми
значениями исключаются. Доверительный интервал рассчитывается при
`n >= 4`. Предпросмотр ограничен 20 строками, максимальное число групп
--- 9 999.

При `max_lag > 0` требуется одно временное поле с `granularity`.
Лаг 1 сопоставляет показатель X месяца t с Y месяца t+1; при пропуске
календарного периода соседние строки не склеиваются. Результат содержит
покрытие периодов, размер пары для каждого лага, корреляцию после первых
разностей как диагностику общего тренда и p-value с поправкой Бонферрони
на все проверенные лаги. Даже исправленное p-value не устраняет возможную
автокорреляцию и не доказывает причинность.

### Статистическая интерпретация

-   `alpha` --- порог для сравнения с p-value; часто используется
    `0.05`, но это не универсальное правило.
-   `confidence_level` --- уровень доверительного интервала, например
    `0.95` для 95%.
-   `p-value` не является вероятностью истинности гипотезы. Он
    показывает, насколько наблюдаемые данные согласуются с нулевой
    гипотезой при используемой статистической модели.
-   Доверительный интервал выражает неопределённость оценки и зависит от
    предположений метода.

Статистическую значимость следует рассматривать вместе с размером
выборки, предметной областью и способом построения групп. Выбор
группировки может существенно изменить вывод.

## 3. Фильтры данных

Общий `DataFilter` поддерживает следующие операторы:

| Оператор   | Значение              | Формат `value`                |
|------------|-----------------------|-------------------------------|
| `eq`       | Равно                 | Одно значение                 |
| `ne`       | Не равно              | Одно значение                 |
| `gt`       | Больше                | Одно значение                 |
| `gte`      | Больше или равно      | Одно значение                 |
| `lt`       | Меньше                | Одно значение                 |
| `lte`      | Меньше или равно      | Одно значение                 |
| `in`       | Входит в набор        | Список значений               |
| `not_in`   | Не входит в набор     | Список значений               |
| `is_null`  | Значение отсутствует  | Обычное значение не требуется |
| `not_null` | Значение присутствует | Обычное значение не требуется |
| `between`  | В диапазоне           | Два граничных значения        |

Пример набора значений:

``` json
{"field": "region", "operator": "in", "value": ["north", "south"]}
```

Пример диапазона:

``` json
{"field": "amount", "operator": "between", "value": [100, 500]}
```

Точная форма `value` для `is_null` и `not_null` определяется валидатором
модели. При сравнении важно учитывать тип столбца: фильтр по текстовому
представлению числа не всегда эквивалентен числовому сравнению.

## 4. Как выбрать метод


| Вопрос                                                                        | Метод          |
|-------------------------------------------------------------------------------|----------------|
| На сколько изменилась метрика между двумя сегментами?                         | `compare`      |
| Стало ли агрегированное значение больше или меньше?                           | `compare`      |
| Как связаны два показателя в разрезе времени или категорий?                   | `relationship` |
| Есть ли положительная или отрицательная линейная корреляция между агрегатами? | `relationship` |


Если требуется установить причину изменения, одного из этих методов
недостаточно: нужны дополнительные предположения, дизайн исследования и
проверка альтернативных объяснений.
