# [P0] Сохранять SQL, результаты и источник при повторном открытии чата

При повторном открытии истории API возвращает текст сообщения без AgentResponse, а UI создаёт пустой tool_results. Связь чата с источником живёт только в localStorage.

Подтверждено изолированным FastAPI-сценарием 24.10.2026 на базе 88975aa: live_tool_results=1, в GET истории результата нет, source_ids отсутствует.

Критерии приёмки:
- Полный проверенный ответ (SQL, таблица, provenance, timing) восстанавливается после перезапуска.
- Сервер хранит привязку к источнику; смена источника в существующем чате отклоняется до вызова LLM.
- Старые SQLite и текстовые чаты читаются без потери данных; миграция повторяемая.
- Исторический snapshot не переписывается при обновлении CSV.
- Интерфейс восстанавливается без localStorage; отсутствующий источник не мешает чтению старого анализа.
- Есть регрессионные backend/frontend проверки и независимое ревью.

Связано с #17, #28, #30, #31. Эта задача не закрывает полный объём контекста диалога, дашбордов или семантики #19.
