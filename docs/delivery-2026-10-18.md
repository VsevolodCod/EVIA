# EVIA: итоговая поставка для review

Conventional Commit / заголовок PR: `feat(evia): integrate BI workspace, contracts and persistent chat`.

Поставка объединяет существующий React-интерфейс и FastAPI команды в локально проверенный стенд EVIA: CSV → источник → схема/предпросмотр/профиль → диалог с агентом → Markdown и реальные результаты инструментов. Исправлены импорт разделителей и потеря/повреждение истории чатов; подключена установленная пользователем Gemma через Ollama, добавлены измерения времени ответа.

## Добавленные возможности

### Интерфейс и диалоги

- React + TypeScript + Vite; модули API, источников, чата, результатов и маскота.
- Загрузка/выбор CSV, реальная схема, preview до 100 строк, профиль по выборке до 500 строк. Размер источника и размер выборки показаны отдельно.
- Markdown/GFM: таблицы, списки и код. Raw HTML/script, опасные ссылки и удалённые изображения не выполняются/не загружаются.
- Пустые состояния, ошибки API, повтор, остановка ожидания; реальные результаты инструментов без фиктивных SQL/графиков.
- Единое имя EVIA, адаптивная компоновка, русские подписи и клавиатурная навигация. 40 состояний маскота, quiet/reduced-motion; отсутствует выдуманный прогресс.
- Первый вопрос создаёт чат через `/chats`; дальнейшие вопросы идут в `/agent/chat` с тем же chat_id. Модель получает предыдущие user/assistant сообщения. «Новый анализ» начинает отдельный диалог.
- История слева группирует диалоги, справа видна вся переписка. Результаты и время каждого ответа привязаны к соответствующему сообщению. Смена источника и поздние ответы не смешивают диалоги.

### Контракты и backend

- Контракт v1 для Source, SourceSchema, DatasetSnapshot, Profile, QueryResult, AgentResponse, Error, включая ссылки chat/artifact/job.
- Отдельные intent/SQL/explanation и фактические columns/rows, лимиты, происхождение результатов; идентификаторы, request_id, ошибки и правила расширения API.
- Общие синтетические fixtures проверяются Pydantic, JSON Schema validator и frontend-парсером. Наличие схем будущих возможностей не выдаётся за уже работающий Data Engine.
- Полная модель Chat отделена от страницы ChatHistoryResponse. Записи добавляются транзакционно через SQLite `BEGIN IMMEDIATE`; устаревший частичный снимок не стирает историю.
- Курсор `before/next_before` стабилен при добавлении новых сообщений. Старый offset сохранён для совместимости. Временные чаты остаются в памяти и используют отдельные копии.

### Ollama и измерения

- Проверена локальная `gemma4:12b` через существующий провайдер Ollama. Веса не скачивались агентом и не добавлялись в git.
- В интерфейсе — прошедшее ожидание, итоговое время и раскрываемые подробности. API возвращает необязательное `timing`: весь агент, вызовы LLM, инструменты, загрузка весов, обработка входа, генерация и токены/с.
- Время измеряется монотонными часами. Ошибка/отмена останавливает таймер, повтор начинает новый. Отсутствующие метрики остаются неизвестными, а не подменяются нулём.
- Добавлены `scripts.benchmark_agent` и `scripts.warm_ollama`; конфигурируемый `OLLAMA_KEEP_ALIVE`. Локально выбран 60m вместо 10m для уменьшения повторных холодных запусков; значение по умолчанию в репозитории — 10m.
- Контекст 4096, локальный лимит 768 токенов и `THINKING=0` не урезались ради результатов benchmark. Предзагрузка переносит затраты на подготовку, а удержание в памяти не ускоряет саму генерацию.

## Исправленные дефекты

1. CSV с `;` разбирался по запятым внутри значений и давал пять неверных столбцов. Единое определение диалекта теперь используется при импорте, схеме, count, preview и profile.
2. Определитель разделителя не обрабатывал CR-only файлы так же, как основной reader. Исправлено открытие буфера пробы с `newline=''`; parser_version повышен до 3.
3. Старые сохранённые схемы оставались неверными. Добавлено однократное обновление схемы при чтении без перезагрузки или изменения исходного CSV.
4. Смешанная ширина в хвосте файла могла скрываться за sampling. Проверяются все строки; повреждённый импорт не публикует частичный источник.
5. Повторный persistent chat использовал DTO страницы вместо Chat и завершался ошибкой. Исправлен тип возвращаемой модели.
6. Последние 50 сообщений принимались за всю историю при сохранении. Запись теперь добавляет сообщения и не удаляет старую историю.
7. Конкурентные сохранения и изменяемые временные объекты могли терять/менять чужие сообщения. Добавлены транзакции, rollback, неизменяемость существующих сообщений и detached-копии.
8. Каждый вопрос UI был самостоятельным запросом без контекста и выглядел новым чатом. Подключено продолжение серверного диалога; создание чата сохраняет ID даже при отмене ожидания.
9. Длинные названия диалогов расширяли/прокручивали левую панель. Ограничена ширина элементов, полное название доступно через title и доступную подпись.
10. Устранены проблемы чистого запуска: инициализация таблиц каталога, async SQLite-зависимости, обработка отсутствующей истории, порядок static mount и завершение дочерних процессов Windows launcher.

## Проверки и фактические результаты

```powershell
npm.cmd test --prefix frontend -- --run
npm.cmd run build --prefix frontend
$env:LLM_PROVIDER = 'mock'
$env:BI_BROWSER_TESTS = '1'
$env:BI_BROWSER_CHANNEL = 'msedge'
.venv\Scripts\python -m pytest -q -ra
```

- Итоговое приложение `95e7055`: **31 frontend-тест**, TypeScript и production build прошли. **72 Python-теста** прошли с учётом отдельного browser-прогона, **2 пропущены** на Windows: POSIX process-group и symlink privilege.
- Полный прогон дал 71 passed и один browser timeout загрузки UI при параллельном запуске Gemma. Повторный отдельный browser-прогон прошёл; после исправления длинного названия истории build и browser acceptance снова прошли. Эта нестабильность не скрывается общим числом тестов.
- Ранее на чистом detached checkout `b77471f` с новой `.venv` и отдельным node_modules: 25 frontend, 58 backend/browser, два platform skips, `pip check` и build успешны. Последующие изменения проверялись отдельно; финальный вариант не выдаётся за повторную установку всех зависимостей в чистом окружении.
- Синтетическая CSV-матрица: 96 сочетаний разделителей/кавычек/переносов/размеров прошли после CR-исправления; исходные байты и ведущие нули сохранены. На локальном источнике «Продажи» подтверждены 500000 строк и 22 поля, preview/profile согласованы.
- Чаты: 80+ сообщений, restart, 12 конкурентных сохранений через два engine, два параллельных HTTP-запроса, rollback, temporary mode, курсор во время добавления, прежний контекст во втором запросе и пустой контекст нового чата.
- Edge + реальный FastAPI: CSV → выбор → схема/профиль → вопрос → Markdown/tool table, клавиатура, 390 px, quiet/reduced-motion, защита от HTML/JS/удалённых изображений. В dev smoke проверен `/chats` через Vite proxy.
- Живая Gemma: успешные `get_source_schema` и `preview_data`, две строки с `0001`/`0002`; тест памяти вернул «маяк-4826» во втором сообщении того же чата.
- Замеры одинакового вопроса схемы: **93.590 с** (в том числе 82.361 с загрузки), **9.988 с**, **9.526 с**. Это сравнение холодного и прогретых запросов, а не доказательство десятикратного ускорения вычислений от изменения кода.

Сырые конкурсные CSV, базы, `.env`, секреты, веса, node_modules, dist и локальные скриншоты не включены в поставку. В git есть только синтетический `sample-data/sales.csv` и синтетические fixtures.

## Известные проблемы и следующий этап

- **#18 остаётся открытой:** после reload UI не восстанавливает список серверных диалогов, источник, результаты и пагинацию. Эта работа отложена по просьбе пользователя.
- **Скриншот пользователя:** длинный ответ в узкой панели выглядит оборванным/неудобным для чтения. Исправление не заявлено. Нужно отдельно сопоставить полный API-ответ с DOM, прокруткой и причиной завершения генерации; из одного скриншота нельзя установить, обрезан ли текст моделью или интерфейсом.
- При сбое/отмене вопрос уже может быть сохранён; повтор HTTP может добавить дубликат. Отмена ожидания не гарантирует остановку генерации. В постоянной истории пока нет tool_results и timing; длинная история ограничена окном модели.
- **#7 остаётся открытой:** UTF-16/Windows-1251, ручной выбор неоднозначного разделителя, `sep=;`, raw/typed-слой, точные денежные значения, аудит девяти оригиналов и заявленные большие лимиты не завершены. Автоопределение четырёх разделителей остаётся эвристикой.
- Нет SQL/DuckDB/Text-to-SQL, PostgreSQL, дашбордов, chart API, авторизации, многопользовательской изоляции и облачного размещения. Период данных по выборке нельзя выдавать за точный min/max полного источника.
