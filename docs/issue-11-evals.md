# Эталонные вопросы для benchmark моделей

## Публичный corpus

`evals/v1/` содержит версионируемый синтетический набор из 20 вопросов и
fixtures без пользовательских или конкурсных строк. Из них 17 случаев
проверяют вычисленный результат, а 3 требуют безопасного уточнения или отказа.

Проверка выполняется тем же путём, что и продукт: CSV загружается через
`SourceService`, gold SQL проходит `SafeQueryExecutor`, а результат сравнивается
по колонкам, порядку строк, NULL и числовому допуску.

```sh
python -m scripts.verify_eval_corpus --output /tmp/evia-eval-corpus.json
```

Ненулевой код означает несовпадение SHA-256 fixture, неприемлемый SQL или
несовпадающий результат. Этот corpus используется как регрессия и как открытая
часть входа для #14.

## Частная проверка набора организаторов

Реальные девять CSV остаются вне репозитория. Для checkpoint выполнен отдельный
локальный manifest, который не коммитится: 20 вопросов (18 вычисляемых, 2
безопасных) на всех девяти источниках. Он содержит только имя файла, SHA-256,
вопрос, gold SQL, имена результирующих колонок и агрегированные результаты;
строки CSV, значения идентификаторов и исходные файлы в Git не попадают.

Вопросы проверяют отличия, которые нельзя терять при оценке модели: товарные
операции и возвраты, обращения, фактические трудозатраты, статусы доставок,
события и сессии, ratio-of-sums для рекламного CTR, суммы закупок, цепочки и
попытки фоновых заданий, а также числовые ID лекарств как категории. Два
вопроса требуют отказа от причинного вывода или уточнения отсутствующего join.

Независимый reviewer должен проверить формулировки и gold SQL по доступному ему
локальному набору перед тем, как #14 использует manifest для выбора модели.
