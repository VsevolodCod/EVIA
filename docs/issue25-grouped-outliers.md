# Анализ аномалий по группам (#25)

Для действия `outliers` агент передаёт `columns=[]` (первое подходящее числовое поле),
`[measure]` (все строки источника) или `[measure, group]` (отдельное сравнение внутри
каждой категории). Имена полей должны точно совпадать с текущей схемой выбранного
источника. Для группы допустимо текстовое, временное или числовое поле, отличное
от показателя. SQL строится приложением, а не копируется из ответа модели.

Для каждой непустой группы берутся только корректные числовые значения показателя.
При менее четырёх значениях кандидаты не определяются. Если Q1 = Q3, нулевой IQR
описывается отдельно для постоянного ряда и ряда с редкими отличающимися значениями.
Иначе кандидатами считаются наблюдения за пределами Q1 − 1,5×IQR и Q3 + 1,5×IQR.
Ответ показывает статистику группы и до 20 кандидатов с наблюдением и порогами.
Если групп больше 20, поиск кандидатов не выполняется: нужно сузить запрос.

Исходные строки не изменяются. Кандидат не доказывает причину отклонения.
Результаты несут provenance текущего snapshot через обычный QueryResult.
Регрессия `test_outliers_compare_heterogeneous_segments_separately` проверяет,
что редкая выручка в A не смешивается с постоянной серией B, а малая группа C
и пустая категория объясняются явно.
