# Надёжный импорт CSV (#7)

`POST /sources/csv` принимает CSV до 512 МиБ. Загрузка читается по частям, оригинальные байты сохраняются без изменений и проверяются SHA-256. Поддерживаются UTF-8 (с BOM и без), UTF-16 (с BOM и без него) и Windows-1251; разделители `,`, `;`, табуляция и `|`, включая преамбулу Excel `sep=;`. Заголовки должны быть непустыми и уникальными. CSV-кавычки, переносы внутри полей и CR/LF/CRLF обрабатываются стандартным CSV-парсером.

Импорт сначала сканирует **весь файл**, проверяет ширину каждой логической строки и определяет типы по всем принятым строкам. Отчёт содержит размер, хеш, кодировку, разделитель, число прочитанных, принятых и отклонённых строк, предупреждения и причины отказа. При повреждённой записи файл целиком отклоняется; частичный источник в каталоге не появляется. Даты с неоднозначным локальным форматом и смешанные числовые/текстовые столбцы остаются текстом с предупреждением. Пустые значения и нулевые префиксы идентификаторов не теряются.

Для каждого снимка создаются две таблицы DuckDB: `source` сохраняет значения строками, `source_typed` содержит строго приведённые типы. Для конечных чисел с точкой или десятичной запятой используется `DECIMAL(38, scale)`, если значение помещается в него; исходная сумма и `SUM` сохраняют десятичную точность. Если значение требует большей точности или не соответствует типу всего столбца, тип остаётся `VARCHAR`, без скрытого превращения непустой ячейки в `NULL`. Оригинал можно скачать в любой момент.

Для повторного импорта передайте `source_id` как multipart-поле в тот же `POST /sources/csv`. Новый файл получает отдельный `snapshot_id`; предыдущие оригиналы и физические таблицы остаются. Ошибочный повторный импорт не меняет текущую версию. `GET /sources/{source_id}/versions` перечисляет версии; `GET /sources/{source_id}/versions/{snapshot_id}/download` отдаёт точные исходные байты. В интерфейсе повторный импорт и отчёт находятся на вкладке «Схема».

Проверка девяти исходных файлов воспроизводится локально:

```bash
python -m scripts.verify_csv_imports '/path/to/прогон таски 5' \
  --report /tmp/evia-csv-audit.json \
  --summary docs/issue-7-originals-audit.json
```

Скрипт создаёт временную базу для каждого файла, сверяет SHA-256 копии и число строк DuckDB с отчётом и удаляет временные данные. [Сводка](issue-7-originals-audit.json) содержит только имена файлов, хеши и технические счётчики; исходные строки и полный локальный отчёт в репозиторий не добавляются.

Ограничения: автоопределение разделителя остаётся эвристическим для файлов без `sep=`; нестандартные и многосимвольные разделители не поддерживаются. Один столбец в CSV допустим, поэтому ошибочно выбранный разделитель в принципе не всегда отличим от настоящего одноколоночного файла. Данные и типы за пределами `DECIMAL(38, scale)` сохраняются как текст. DuckDB возвращает `AVG(DECIMAL)` как число с плавающей точкой, поэтому для денежных средних требуется отдельное согласование округления результата. Новый импорт требует свободного места для оригинала, нормализованной копии и DuckDB-таблиц. Профиль и графики интерфейса по-прежнему строятся по ограниченной выборке; это не ограничивает полноту проверки импорта и схему.
