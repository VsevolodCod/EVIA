# Метод аудита исходных CSV

Локальный аудитор фиксирует для каждого файла SHA-256, размер, кодировку,
разделитель, число строк и агрегированную схему. Он не сохраняет и не
публикует raw rows, значения ячеек или исходные CSV.

Повторный запуск над теми же байтами должен вернуть те же hash и metadata.
Кандидаты ключей, в том числе двух- и трёхколоночный grain, дат, десятичных
значений, NULL, возвратов, событий, сессий, попыток и цепочек являются
эвристиками для последующей проверки командой данных: они не подтверждают
бизнес-смысл автоматически.

Ограничения: распознаются UTF-8, UTF-8 BOM, UTF-16 и Windows-1251; сложные
форматы и неоднозначные разделители требуют ручной проверки. Публичный отчёт
не содержит имён файлов, заголовков или сведений, позволяющих восстановить
данные.

## Локальный запуск

Исходные файлы и manifest остаются вне репозитория. После получения набора из
девяти CSV запустите:

```bash
python -m scripts.audit_datasets \
  --input /путь/к/HK_Datasets \
  --output /путь/вне-репозитория/audit-manifest.json \
  --public-report /путь/вне-репозитория/audit-method.md
```

Команда прервётся, если в каталоге не ровно девять CSV. Передавать
`--expected-files` допустимо только для синтетической проверки аудитора.
