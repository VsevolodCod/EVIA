# Аудит набора организаторов — 18 октября 2026

## Что проверено

Аудитор выполнен локально над полным набором из девяти CSV. Исходные файлы,
значения ячеек и JSON-manifest с именами, хешами и схемами находятся вне
репозитория. В git сохранены только процедура и выводы, достаточные для
планирования Data Engine.

Набор содержит 5 376 000 записей общим объёмом около 1,38 GiB. Каждый файл
имеет UTF-8 BOM и разделитель `;`. Повторный запуск над теми же файлами
создаёт тот же локальный manifest.

## Итоги для реализации

- Восемь источников имеют уникальный идентификатор записи; у девятого
  подтверждён составной grain из даты и двух идентификаторов справочников.
- В наборе есть временные поля, значения с десятичной запятой, NULL, возвраты,
  события и сессии, а также цепочки запусков и номера попыток. Это покрывает
  проверочные классы данных из #5.
- Несколько датасетов содержат поля, применимые только к отдельным статусам.
  В следующем этапе нельзя интерпретировать пустое значение как ноль.
- Для денежных и весовых показателей требуется явное преобразование
  десятичной запятой при загрузке в DuckDB (#7/#8); идентификаторы должны
  оставаться строками, чтобы не потерять ведущие нули.

## Расхождения и исправления

- Все девять ожидаемых файлов присутствуют: расхождения в количестве файлов
  нет.
- В документации проекта набор ранее был назван «кейсом 2», тогда как README
  набора организаторов называет его «кейсом 1». Для команды источником истины
  остаётся ссылка организаторов и содержимое набора; номер кейса не должен
  попадать в API или код.
- Реальные строки выявили ошибку выбора разделителя: CSV с `;` и десятичной
  запятой мог ошибочно распознаваться как comma-delimited. Добавлен
  регрессионный тест и исправлен общий детектор формата.

## Ограничения

Аудит определяет технические признаки и потенциальный grain, но не
подтверждает бизнес-связи, семантику статусов или пригодность метрик. Эти
проверки относятся к профилированию, DuckDB-импорту и эталонным SQL в #7–#11.
