# Линза BI

Локальное рабочее пространство для исследования CSV: источники и история слева, данные в центре, чат с помощником Эвией справа. Интерфейс подключён к FastAPI команды и показывает фактические ответы и результаты инструментов.

## Быстрый запуск

Нужны **Python 3.11+** и **Node.js 22.12+ или 24+** с npm. Подготовка зависимостей требует сети; после подготовки интерфейс и mock-режим запускаются локально без скачиваний. Для Ollama заранее установите runtime и выбранную командой модель.

Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm ci --prefix frontend
npm --prefix frontend run build
python scripts/run.py
```

В Windows используйте `python -m venv .venv`, затем `.venv\Scripts\Activate.ps1`; остальные команды те же. Запуск проверен на macOS, команды Windows пока не проверены.

Откройте **http://127.0.0.1:8000**. API-документация: **http://127.0.0.1:8000/docs**. `Ctrl+C` завершает процессы, созданные launcher. Готовое приложение обслуживается одним FastAPI; Node.js нужен для подготовки сборки, а не для её дальнейшего запуска.

### Первое исследование

1. Загрузите `sample-data/sales.csv` — это небольшой синтетический пример, не конкурсные данные.
2. Выберите источник. Посмотрите строки, схему и профиль. Идентификаторы `0001` и `0002` должны сохранить ведущие нули.
3. Задайте вопрос, например «Что есть в данных?». Выбранный `source_id` передаётся агенту.
4. Ответ поддерживает Markdown, списки, таблицы и блоки кода. Результаты инструментов отображаются отдельно от предпросмотра исходного CSV.
5. Начните новый анализ или выберите предыдущий диалог в истории. История хранится только в памяти текущей вкладки; перезагрузка её очищает.

При `LLM_PROVIDER=mock` показан демонстрационный режим: он проверяет интеграцию и возвращает тестовый ответ, **не выполняет аналитический SQL**. Поведение mock-провайдера унаследовано от команды: первый запрос вызывает `list_sources`, следующие могут вернуть только текст.

## Разработка

После установки зависимостей, из активированной `.venv`:

```sh
python scripts/run.py --dev
```

Откройте **http://127.0.0.1:5173**. Launcher запускает FastAPI на 8000 и Vite на 5173. Vite проксирует `/health`, `/sources` и `/agent` к API; CORS и отдельный публичный API не нужны. Изменения frontend обновляются автоматически. После изменения Python перезапустите launcher.

Другие порты:

```sh
python scripts/run.py --dev --port 8100 --ui-port 5200
```

Порты должны быть свободны и различаться. Для запуска Vite отдельно задайте `BI_API_TARGET` (по умолчанию `http://127.0.0.1:8000`). Launcher устанавливает его автоматически. Параметр `--host` по умолчанию ограничивает доступ локальной машиной. Авторизация и многопользовательская изоляция в этом прототипе не реализованы; это локальный инструмент.

## Локальная модель и данные

При необходимости скопируйте `.env.example` в `.env`. Основные настройки:

| Переменная | Назначение |
| --- | --- |
| `LLM_PROVIDER` | `mock` по умолчанию; `ollama` для локальной модели |
| `LLM_MODEL` | Точное имя уже установленной модели из `ollama list` |
| `OLLAMA_BASE_URL` | По умолчанию `http://127.0.0.1:11434` |
| `TIMEOUT` | Таймаут провайдера модели в секундах |
| `AGENT_MAX_STEPS` | Ограничение числа шагов агента |
| `BI_DATA_DIR` | Каталог исходных CSV (по умолчанию `data/`) |
| `BI_CATALOG_DB` | SQLite-каталог источников (по умолчанию `data/catalog.sqlite3`) |

CSV и каталог сохраняются backend на локальном диске. Browser storage используется только для настройки тихого режима, не для файлов, вопросов или ответов. Не коммитьте `.env`, `data/`, веса моделей, конкурсные CSV и логи. Шрифты системные, пакеты входят в сборку; frontend не использует CDN, облачные сервисы или телеметрию.

Эвия показывает состояние выполняемого запроса. Тихий режим и системная настройка `prefers-reduced-motion` отключают движение. Показ этапов не имитирует внутренний прогресс модели. Кнопка остановки прекращает ожидание ответа в браузере; API пока не гарантирует отмену вычисления на сервере.

## API-контракт интерфейса

| Метод и путь | Запрос / результат |
| --- | --- |
| `GET /health` | `{status, llm_provider}` |
| `GET /sources` | `DataSource[]`: `source_id`, `name`, `source_type`, `status`, `created_at`, `schema_version` |
| `POST /sources/csv` | multipart `file`, необязательное `name`; возвращает `DataSource` |
| `GET /sources/{id}/schema` | `SourceSchema` с `objects[].fields`, `row_count`, `relations` |
| `GET /sources/{id}/preview?limit=100` | Массив строк; допустимый limit 1–100 |
| `GET /sources/{id}/profile` | `sample_size`, `sample_limit`, `columns`, `note` |
| `POST /agent/ask` | `{question, source_ids: [id]}` → `{answer, steps, tool_results}` |

Элемент `tool_results`: `{tool_name, ok, data, error}`. `data` может быть массивом строк, объектом или скаляром; UI не трактует любой результат как выполненный SQL. Ошибка инструмента сохраняется видимой даже при наличии текстового ответа. Схема даёт точное число строк; статистика профиля рассчитана на ограниченной выборке (сейчас до 500 строк).

API агента пока принимает один самостоятельный вопрос без `session_id` или истории сообщений. UI сохраняет выбранный источник и историю для удобства пользователя, но это **не память модели**. Для следующего аналитического вопроса формулируйте условия полностью.

## Проверки

```sh
npm --prefix frontend test
npm --prefix frontend run build
python -m pytest -q
```

Frontend: типы, сборка и тесты интерфейса/контрактов, Markdown и изоляции состояния. Backend: исходные тесты команды, реальный FastAPI-сценарий загрузки → схема → предпросмотр → профиль → агент, отдача статических ресурсов и launcher. Тесты используют временные каталоги и синтетические данные.

Перед PR также проверяется живой запуск через HTTP. Browser-проверка макета зависит от наличия подключённого браузера; её отсутствие указывается в отчёте, а не считается успешной проверкой.

## Структура

```text

  web.py            необязательная раздача frontend/dist после API-маршрутов

sample-data/        только синтетические учебные примеры
```

## Текущие ограничения и ответственность

- Backend в `tes/pipeline_1` поддерживает **UTF-8 CSV с запятой**. Конкурсный разделитель `;`, кодировки и расширенное определение типов — работа Data Engine (участник B). Такие файлы сейчас нельзя считать корректно импортированными только потому, что API их принял.
- SQL-исполнитель, DuckDB и полный Text-to-SQL — зависимости от участников A/B. В этой задаче нет самостоятельно вычисленных UI-агрегатов, выдуманных графиков или готовых ответов по конкурсным данным.
- Сохранённые дашборды, постоянные сессии, серверная память диалога, PostgreSQL-коннектор, авторизация и масштабирование относятся к следующим задачам.
- Профилирование и загрузка в текущем backend синхронные. Ограничения больших файлов и конкурентных запросов нужно закрыть до многопользовательского развёртывания.

Issue #1 ограничена рабочим интерфейсом и локальной интеграцией. PR направлен в ветку backend `tes/pipeline_1`; после её принятия командой изменения могут быть включены в `main` обычным review-процессом.

## Маскот EVIA: 40 состояний

Используется предоставленный автором `EVIA_mascot_integration_pack`: все 40 прозрачных SVG сохранены без изменений в `frontend/public/mascot/`. Это упрощённая векторная версия дизайна, а не 3D-модель. Типизированный каталог: `frontend/src/features/mascot/states.ts`, компонент: `frontend/src/components/EviaMascot.tsx`.

```tsx
<EviaMascot state="welcome" size={128} />
<EviaMascot state="analyzing" size={96} decorative quiet />
```

Галерея: **http://127.0.0.1:8000/?mascot=1** (замените порт на выбранный при запуске). Все состояния можно выбирать вручную, сравнивать размеры 64–256 px и отключать движение. Карточки галереи статичны; анимируется только выбранный персонаж. Галерея не запускает API-запросов и не меняет рабочие данные.

В рабочем пространстве загрузка CSV включает `uploading`, успешная загрузка — `uploaded`, ошибки формата — `invalid_csv`, ввод вопроса — `listening`, ожидание агента — `thinking`, повтор — `retrying`, полученный ответ — `explaining`, ошибки инструментов — `warning`. Прекращение ожидания — `cancelled`; серверная обработка при этом может продолжаться. Ошибки сети, доступа и таймаута определяются по типу ошибки/HTTP-статусу. Загрузка метаданных сопровождается `profiling`, пустая таблица — `empty_table`. Состояние запроса остаётся привязано к своему источнику.

У API нет событий отдельных этапов агента. Поэтому `analyzing`, `validating`, `calculating`, графики, дашборды, экспорт и прочие дополнительные состояния доступны компоненту и галерее, но не включаются по вымышленному таймеру или догадке из текста LLM. Mock не считается признаком локального LLM и не включает `offline`.

Анимация — мягкое появление и парение всего SVG. Независимая анимация глаз и рук, 3D и скелетная анимация не входят в этот набор. `quiet`, тихий режим приложения и `prefers-reduced-motion` отключают движение. Рядом с маскотом в чате всегда есть текстовый статус; самостоятельный компонент имеет русское альтернативное описание, `decorative` отключает дублирующее озвучивание.

После обновления из worktree пересоберите frontend и перезапустите launcher:

```sh
npm --prefix frontend run build
.venv/bin/python scripts/run.py --port 8100
```
